# `ReadingOutput` JSON schema reference

This document is the human-readable companion to the machine-readable
[`json-schema.json`](json-schema.json) (auto-generated by
`scripts/generate_schema_json.py` from `app/reading/schema.py`).

It is the contract every downstream consumer (CLI, future LLM narrators,
frontend, RAG layers) builds against. The schema is versioned via
`Meta.schema_version`; breaking changes require a major version bump.

**Current schema version:** `1.0.0`
**Stability:** `experimental` (until the first non-engine downstream consumer ships)

---

## Top-level shape — 9 keys

A `ReadingOutput` document has exactly nine top-level keys, mirroring the
pipeline stages 1–8 (spec Section 6). `extra="forbid"` on every model means
the schema rejects any extra key.

| Key | Stage | Pydantic model |
|-----|-------|----------------|
| `meta` | — | `Meta` |
| `chart` | 1 | `ChartBlock` |
| `primitives` | 2 (Tier-0) | `PrimitivesBlock` |
| `foundations` | 3 (Tier-1) | `FoundationsBlock` |
| `practitioner` | 4 (Tier-2) | `PractitionerBlock` |
| `sequences` | 5 | `SequencesBlock` |
| `domains` | 6 | `DomainsBlock` |
| `contradictions` | 8.3 | `list[Contradiction]` |
| `warnings` | — | `list[str]` |

## `Meta` envelope

Engine + chart-input metadata. Every reading is self-describing about which
engine version, ephemeris version, doctrine variant, and Python interpreter
produced it.

| Field | Type | Notes |
|-------|------|-------|
| `schema_version` | `Literal["1.0.0"]` | Bumps with schema changes. |
| `stability` | `"experimental" \| "beta" \| "stable"` | Stability tier of the contract. |
| `engine_version` | `str` | App version emitting the output. |
| `swiss_ephemeris_version` | `str` | Pinned for reproducibility. |
| `python_version` | `str` | Interpreter version. |
| `generated_at` | `str` (ISO-8601 UTC) | Wall-clock UTC. |
| `chart_input` | `ChartInput` | Echoes the user-supplied birth data. |
| `doctrines_used` | `list[str]` | Free-form labels for active doctrine sources. |
| `doctrine_config` | `DoctrineConfig` | Locked decisions D-1..D-16 (see below). |
| `enrichment_enabled` | `bool` | Whether Tier-3 ran. |
| `robustness_enabled` | `bool` | Whether birth-time robustness ran. |
| `stage_timings_ms` | `dict[str, int]` | Per-stage wall-clock. |
| `schema_changelog_url` | `str` | Defaults to `docs/reading/CHANGELOG.md`. |

## `Finding` — the universal output unit

Every engine module emits its judgments as `Finding` instances. Tier-3
enrichments are inline so consumers never need a JOIN.

### Required fields

| Field | Type | Notes |
|-------|------|-------|
| `id` | `str` | Stable across runs; see ID grammar below. |
| `rule` | `str` | Human-readable rule name. |
| `source_sequence` | `str \| None` | Which named sequence emitted this (if any). |
| `classification` | `"promise" \| "trigger" \| "affliction" \| "yoga" \| "primitive"` | Closed set. |
| `direction` | `"positive" \| "negative" \| "neutral" \| "mixed"` | Closed set. |
| `verdict` | `str` | `max_length=140` — short, declarative. |
| `verdict_language` | `Literal["en"]` | English-only in 1.0.0. |
| `evidence` | `list[str]` | Free-form supporting facts. |
| `confidence` | `ConfidenceScore` | 3-vote rule envelope. |

### Tier-3 enrichment fields

These fields are populated only when `--no-enrich` is **off**. Defaults
distinguish "Tier-3 disabled" from "Tier-3 ran but found nothing."

| Field | Type | Default | Purpose |
|-------|------|---------|---------|
| `enrichment_level` | `Literal[0, 1, 2, 3]` | `0` | Highest Tier reached for this finding. |
| `citations` | `list[Citation]` | `[]` | RAG-attached doctrine snippets. |
| `consensus` | `ConsensusScore \| None` | `None` | Cross-source agreement score. |
| `consensus_status` | `"not_computed" \| "no_agreement" \| "computed"` | `"not_computed"` | Why `consensus` is what it is. |
| `dispute` | `Dispute \| None` | `None` | Report-only doctrine variance. |
| `robustness` | `RobustnessScore \| None` | `None` | Birth-time sensitivity. |
| `contradicts_finding_ids` | `list[str]` | `[]` | Sibling findings this disagrees with. |

### ID grammar (stable across runs)

Enumeration-based IDs (e.g. `finding_001`) are **forbidden**. Every ID must
be derivable from the rule itself:

| Pattern | Example |
|---------|---------|
| `seq_<N>.<scope>.<rule_slug>` | `seq_5.md_3.step_05_rashi_depositor` |
| `primitive.<module>.<rule_slug>` | `primitive.karakas.atmakaraka` |
| `foundation.<module>.<rule_slug>` | `foundation.argala.7th_house_argala` |
| `practitioner.<module>.<rule_slug>` | `practitioner.mks.saturn_in_1` |
| `domain.<name>.<rule_slug>` | `domain.marriage.7l_dasha_window` |

## Tier-3 sub-models

### `Citation`

| Field | Type | Constraints |
|-------|------|-------------|
| `source` | `str` | Doctrine source label (`BPHS_47_3`, etc). |
| `passage` | `str` | Raw text snippet. |
| `relevance` | `float` | `[0, 1]` cosine relevance. |
| `knowledge_doc_id` | `str` | Pointer into the knowledge library. |

### `ConsensusScore`

| Field | Type | Constraints |
|-------|------|-------------|
| `score` | `float` | `[0, 1]`. |
| `sources_agreeing` | `int` | `>= 0`. |
| `sources_total` | `int` | `>= 0`. |
| `low_consensus_flag` | `bool` | `True` if `score < doctrine_config.consensus_agreement_threshold`. |

### `Dispute`

Report-only — carries **no** `is_correct` / `recommended_side` field by
design (spec Section 14 Tier-3 methodology commitment).

| Field | Type | Notes |
|-------|------|-------|
| `rule` | `str` | The disputed rule. |
| `sources_for` | `list[str]` | Sources affirming. |
| `sources_against` | `list[str]` | Sources opposing. |
| `canonical_example` | `str \| None` | Worked example illustrating the dispute. |

### `RobustnessScore`

Output of `birth_time_robustness.py`. `sensitive_to_birth_time` is marked
`EXPERIMENTAL` until the threshold methodology is published (Section 14).

| Field | Type | Constraints |
|-------|------|-------------|
| `sensitive_to_birth_time` | `bool` | |
| `flip_rate_at_5min` | `float` | `[0, 1]`. Fraction of judgments that flip when birth time perturbs ±5 min. |
| `flip_rate_at_10min` | `float` | `[0, 1]`. |
| `inputs_used` | `list[str]` | Findings included in the sensitivity sweep. |

### `ConfidenceScore`

The 3-vote rule envelope (house, lord, karaka).

| Field | Type | Constraints |
|-------|------|-------------|
| `score` | `float` | `[0, 1]` aggregate. |
| `votes` | `dict[str, bool]` | Fixed keys `{house, lord, karaka}`. |
| `band` | `"indicative_only" \| "low" \| "medium" \| "high" \| "very_strong"` | Human bucket. |

A Vimshottari Mahadasha judgment. The 19-key `checks` dict is validated to
match `MD_CHECK_KEYS` exactly (adding/dropping a check requires a spec

9. `trinal_planets`

11. `md_lord_as_lagna_yogas`
12. `nakshatra_tara_from_moon`
13. `nakshatra_depositor_dignity`

### `ADJudgment` — 7 named checks

A Vimshottari Antardasha judgment. The 7-key `checks` dict is validated to
match `AD_CHECK_KEYS` exactly.

Fields mirror `MDJudgment` plus `ad_lord`.

The 7 check keys:

1. `rulership_of_ad_lord`
2. `house_placement_of_ad_lord`
3. `strength_dignity_influence`
4. `rajyoga_formed`
5. `afflictions`

BPHS layered Varga judgment. Steps:

Career Executive Consulting sequence:

## `Contradiction`

Top-level cross-finding disagreement detected by
`contradiction_detector.py`.

| Field | Type | Notes |
|-------|------|-------|
| `finding_ids` | `list[str]` | `min_length=2` — the conflicting Findings. |
| `domain` | `str` | Which domain (or `"cross-domain"`). |
| `description` | `str` | Why they disagree. |
| `severity` | `"soft" \| "hard"` | Soft = both stand; hard = at least one yields. |
| `suggested_arbitration` | `str \| None` | Descriptive only — never picks a winner. |

## Stage blocks (envelopes)

`ChartBlock`, `PrimitivesBlock`, `FoundationsBlock`, `PractitionerBlock`,
`SequencesBlock`, `DomainsBlock` are thin envelopes. The interesting shapes
are the `Finding` lists they carry; the block models exist to satisfy
`ReadingOutput` composition and lock `extra="forbid"`.

`PrimitivesBlock`, `FoundationsBlock`, `PractitionerBlock` each expose:

- `findings: list[Finding]` — the flat list.
- `by_module: dict[str, list[Finding]]` — pre-grouped for downstream UI.
