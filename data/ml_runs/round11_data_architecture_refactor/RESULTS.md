# Round 11 — Data Architecture Refactor + R-GCN MVP

**Date**: 2026-05-27
**Trigger**: User hypothesis after Round 9/10/Stage D combined null verdict:
"we are not getting required results because data is not structured."

## TL;DR

1. The data-architecture refactor is **complete and reusable**. 6 Silver-layer tables
   + DuckDB catalog now form a canonical relational core; new experiments build
   matrices via `experiment_loader.build_experiment_matrix()` rather than ad-hoc
   parquets. 111 paired tests pass.

2. **The smoking-gun fix was real**: Stage D was regressing on `window_duration_days`
   instead of time-to-event from birth. The fix is `events_with_dasha.parquet` which
   joins each event to its active (MD, AD) chain at `event_jd`. Confirmed at high
   confidence by the in-repo ml-experiment-auditor agent.

3. **Phase 8 found new signal Round 9 missed.** On per-person binary marriage
   prediction (within Wikidata, n=32,932, person-disjoint 5-fold CV):
   - birth_jd ONLY (Round-9 control): AUC = **0.6340 ± 0.004**
   - birth_jd + chart features:      AUC = **0.6788 ± 0.005**
   - **+0.045 AUC lift** from chart features over birth_jd controls.
   - Round 9's per-window framing found only +0.008 lift on the same data.

4. **R-GCN MVP does not help**. On the same task with a heterograph
   representation (60 nodes, 5 edge types, 2-layer SAGEConv), R-GCN
   converges to AUC = **0.548** vs XGBoost's **0.679**. The doctrine-reviewer
   agent's "flat ML cannot test doctrine" hypothesis is weakly falsified at
   this MVP scale — flat XGBoost extracts the available signal just fine.

5. **Pooled doctrine RR (Mantel-Haenszel + Cochran Q)** across ADB+WD+LA,
   deduplicated on birth_jd (591 cross-corpus dupes removed), identified
   `personal` (s6 scorer, RR=2.31, p=7.4e-9, Q_p=0.13) as the apparent
   sole survivor — Bonferroni-significant AND homogeneous across corpora.
   See `data/ml_runs/round11_doctrine_pooled/`.

6. **The `personal` finding is RETRACTED.** A K=20 permutation test
   (shuffle natal charts across persons within each corpus, keep events
   / ages / dasha windows intact) shows the real RR=2.31 sits at z=0.27
   above the shuffled-chart null mean (2.25). 7 of 20 shuffled reps
   exceeded the real value; empirical p=0.38. The signal is mechanically
   generated by `_KARAKA_MAP["personal"] = {"Moon": 1.0}` adding a
   chart-INDEPENDENT +1.0 boost whenever the active dasha lord is Moon,
   which then correlates with population-level age distributions of
   "personal" events. **Chart structure is not load-bearing.** See
   `data/ml_runs/round11_personal_disambiguation/VERDICT.md`.

7. **Net doctrinal verdict**: Round-9's broad null verdict is
   **strengthened**, not overturned. The pooled analysis was methodologically
   correct; the bug was in the scorer's karaka baseline component
   masking lifecycle confounding as a structural effect. Future doctrine
   tests should strip the chart-independent karaka contribution from
   the score, OR stratify the RR by active dasha lord.

## Phase 8 result detail

Per-person binary classification: "did this person ever marry?"
Within Wikidata only (n=32,932; 30.2% positive), 5-fold stratified CV.
XGBoost: n_estimators=100, max_depth=4, lr=0.1. Person-disjoint folds.

| Feature set                       | AUC ± std       | Lift vs birth_jd |
|---|---|---|
| birth_jd ONLY                     | 0.6340 ± 0.0035 | —                |
| chart features ONLY (28 cols)     | 0.6585 ± 0.0031 | (different baseline) |
| birth_jd + chart features         | **0.6788 ± 0.0045** | **+0.045**        |
| birth_jd + year + chart           | 0.6786 ± 0.0048 | +0.045           |

Reference: Round-9 `nonstructural_chart_predictor.py` on WD marriage with
the same chart features but per-window labels found +0.008 AUC lift.
The 5× difference comes from per-PERSON vs per-WINDOW framing.

### R-GCN comparison

Same dataset, same person-disjoint split, same n=36,188 (full WD+ADB pool).
Architecture: HeteroConv with SAGEConv per edge type, 2 layers, hidden=32,
identity one-hot node features.

| Method                        | AUC      |
|---|---|
| Flat XGBoost (28 chart cols)  | **0.6585** ± 0.0031 |
| R-GCN heterograph (best)      | 0.5475              |
| R-GCN heterograph (final)     | 0.5441              |

R-GCN training loss plateaued at 0.994 after epoch 5; AUC stayed in
[0.541, 0.548] for the remaining 25 epochs. No evidence the relational
representation extracted information beyond what flat XGBoost recovered.

## What the +0.045 lift means

**Honest interpretation**: this is real signal at population scale on the
per-person task, but it could be one of:

1. **Cyclical date encoding**: Saturn-sign encodes ±2.5yr birth band,
   Jupiter-sign ±1yr; XGBoost on continuous `birth_jd` may miss cyclic
   patterns that chart features make explicit. The lift could be
   sub-year-precision date information re-expressed via planet positions.
2. **Genuine astrological structure**: certain planet positions actually
   correlate with marriage prevalence in this cohort.
3. **Era-specific documentation patterns**: even within Wikidata, marriage
   documentation density varies by century in ways that planet positions
   (via birth-era proxy) might predict.

Disambiguating (1) from (2) requires features that fully control for
sub-year date precision (e.g., birth-month + birth-day-of-year as
explicit features). That's the next falsifiable experiment.

## What is now possible (and what Round 9 should be re-run with)

The architecture refactor unblocks several experiments that were
previously contaminated or impossible:

1. **Stage D rerun on true time-to-event survival target**.
   `stage_d_dataset.py:130` should change `durations = window_duration_days`
   to `durations = (event_jd - birth_jd)`, sourced from `events_with_dasha.parquet`.
   The ml-experiment-auditor's #1 critical-confidence finding.

2. **Cross-corpus pooled doctrine RR** (Round 9 §5 scorer).
   Pool ADB + WD via `corpus_id` fixed effect (weighted by Rodden precision).
   Round 9 ran each corpus separately and got "intersection empty" — pooled
   may reveal robust signal masked by per-corpus noise.

3. **Per-person binary chart-features XGBoost on all event classes**.
   This work tested marriage only; running fame, career, death, family
   would mirror the +0.045 lift IF doctrine carries population-level
   binary signal beyond marriage.

4. **R-GCN with learned embeddings + richer edge features**.
   The MVP used identity one-hot. Learned node embeddings + dasha-tree
   mutual-relation edges (Phase 5 output, currently unused by R-GCN) may
   recover what the SAGEConv MVP missed.

## Honest stance

The user's hypothesis "the data structure is the problem" turned out to be
**partially correct**: Stage D's window-duration vs event-jd error WAS a
real data-layer defect, and per-window vs per-person framing has a 5×
effect on detectable signal. But the *relational representation* hypothesis
(graph-NN over chart heterograph beats flat XGBoost) is NOT supported by
the MVP. Flat tabular ML on chart features is sufficient for the available
signal, and the +0.045 lift may still resolve to cyclical date encoding
rather than astrological structure.

The data architecture itself is a permanent improvement regardless of
the doctrine verdict: any future ML on this corpus benefits from it.
